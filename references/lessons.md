# 可复用经验与误判防线

本页总结通用流程经验，不携带原使用者的路径、身份、执行数字或批准记录。任何旧经验都不能替代当前机器盘点。

## 清理的对象先拆开

“Claude”可能指 Desktop、Code CLI、内部工作容器、浏览器站点、IDE 插件或第三方专属服务。同一个名称不证明这些对象独占，也不证明用户要求了全部卸载。“本机登录痕迹”与远端账号、聊天、同步设备和备份是不同范围。

每轮先读取并校验使用者自己的保护声明，确认只读、账号维护或完整卸载模式，再形成具体对象与动作。旧批准不能迁移为新用户、新机器或新一轮的删除授权。

## 原项目、内部旧稿和登录材料分别判断

外部项目保持保护；卸载目录中的 VM、会话工作区和用户技能可能包含尚未导出的成果。先只读识别格式与来源，复制已确认的工作材料并逐文件校验。无法提取或价值未知时保留该容器，不用“缓存”二字代替判断。

保留目录必须解释用途：它是内部成果副本，不是原项目运行依赖，也不自动是登录恢复备份。数量应按类型统计，文件数不等于成品文档数。

三种结论不可混用：

| 检查 | 能支持的结论 | 不能据此推出 |
|---|---|---|
| 源与提取副本哈希一致 | 所检查文件成功复制 | 副本在外部已有相同原件 |
| 在指定原项目中找到相同哈希 | 比较范围内存在字节一致副本 | 所有不同版本都没价值 |
| 元数据前后未变 | 所检查路径、大小等未发现变化 | 全部文件内容逐字节相同 |

用户只问用途时不要删除。用户说“没用就删”时先判断条件；不同版本或用途未知的材料不能自行归为无用。

## 浏览器记录有不同计数层级

一个 Chrome Profile 不等于一个网页账号。界面行、URL、访问次数、唯一下载对象和来源链行数也不是同一单位。下载记录与下载实体分开处理：删除记录不需要删除工作文档。

分区 Cookie 可能关联扩展来源；扩展卸载不证明对应 Cookie 消失。Cookie 存在也不证明账号仍能登录。隐藏或已取消的下载记录可能无法在当前 UI 中选择，UI 空白不证明持久库为零。

先走当前浏览器精确管理界面，再在写入源正常退出后只读复核。锁定、未知结构和权限不足记为未核验。不能为追求零残留清空整个 Profile、所有站点或直接修改 SQLite/LevelDB。

## 当前安装与历史登记分别验证

Office 或 IDE 的共享缓存出现目标资产标识，可能仅是历史登记。当前加载项、专属存储、混合缓存和文档内嵌关系应分别核对。未发现当前插件不能写成“已卸载”，混合缓存也不能整体清空。

现有空白文档可能是未保存工作。验证需要测试文档时新建并标识自己的临时文件，不关闭或写入用户现有文档。检查程序是否退出应读进程状态，避免调用会再次打开它的工具。

## UI 操作需要持续核准身份

每次删除后列表都可能变化。重新读取当前窗口、Profile、选中对象和元素标识，不沿用旧截图坐标或把显示行号当元素 ID。搜索词输入后读回全文；焦点变化不能靠猜测补点。

扩展卸载可能打开反馈页并留下新历史。关闭本轮页面即可，不提交反馈；精确关联的新记录纳入既有范围核验。恢复窗口时检查实际非目标标签，Profile 选择页或空白窗口不算恢复成功。

## 删除方式在动作前说清

移入废纸篓仍占空间，也可能仍保有凭据；直接永久删除不会显示在废纸篓。批次表和交付都说明实际方式、恢复位置和容量口径。逻辑字节不等于释放磁盘空间，尤其在克隆、稀疏文件和快照存在时。

报告只读导出不授予操作权限，备份成功不证明秘密已消失。完整卸载默认仅保全成果；敏感恢复副本需要单独明确接受，并保留其用途和处置说明。

## 结论必须与证据同范围

一项残留不阻止其他独立已授权批次继续，但残留不能写成已删除。相同 UI 方法反复失败后应查证新的精确方法，不能机械循环或扩大范围。

历史报告丢失时，建立新的核查记录并标注证据来源；不能伪造原始台账。最终报告从同一终态生成，区分已删除、移入废纸篓、保留、未发现、残留和未核验。成功标准是每个批准对象都有可验证终态，保护材料未被误删，而非承诺所有本地、远端和物理痕迹归零。
