# 各类对象的发现、操作和验收

按当前范围读相应部分。位置、域名和 ID 是发现线索，先核准本轮归属，不能直接批量删除。需要查新版本接口时用官方资料，记录查证时间；不把旧 UI 路径或网上脚本当现行事实。

## App、CLI、专属网关与系统集成

1. 从 `/Applications`、`~/Applications`、用户常见 CLI 安装位置、`~/Library/LaunchAgents` 等有限目录查名称，再核实 bundle ID、版本、签名/可执行路径、安装管理器与依赖。
2. App 与数据分别登记：Application Support、Caches、Logs、Preferences、Saved Application State、WebKit、HTTPStorages、容器、扩展/native host、专属入口。检查容器与内部磁盘是否有产出，见工作成果参考。
3. `~/.claude`、`~/.claude.json`、`~/.local/bin/claude`、`~/.local/share/claude`、`~/.local/state/claude` 是常见发现线索；用户自建网关位置从有效本地配置或当前明确声明取得。目录内容可能混用；不要打印完整配置，不调用可能读取 Keychain 的 credential helper 来“验证”。
4. 用户项目中的 `.claude`、`.mcp.json`、`CLAUDE.md` 与技能是用户资产。先识别专属运行缓存和嵌套备份；即便删除其中一个已批准嵌套对象，也不能删除外层项目。
5. 专属网关必须证实启动项、脚本、进程、监听端口和使用者对应。端口相同不证明身份，名称包含 Claude 不证明独占。正常退出 App、停止确认专属服务后复核 PID/监听；不要按端口盲杀、`killall node` 或卸载共享运行时。
6. 删除前复查路径身份和批准清单；不跟随符号链接，不跨挂载点递归，不把父子路径重复计数。CLI 包管理器卸载仅在确认不连带删除共享依赖时使用。
7. 验证源路径、相关启动登记、进程、监听、专属入口消失。只剩空目录时使用空目录删除，不用递归删除扩大范围。不要为了查“是否退出”调用会自动打开 App 的工具。

保留并核验原活跃网络/VPN、系统出口、其他 AI 工具、共享运行时及 MCP 等。读取系统服务/进程输出时只取 PID、名称、可执行路径及必要状态，不输出含密钥的完整命令参数或环境变量。

## Keychain 与 shell

- 先用元数据精确匹配 service、项目类型与账户身份（对外脱敏），区分同 service 多项。历史 `Claude Code-credentials`、`Claude Safe Storage` 只能作为查询线索。
- 常规盘点不使用显示密码/秘密数据的选项，不全库导出，不因服务名里有 Anthropic 就撤销多产品共享凭据。混合 bundle、独立配置根的命名空间和文件型凭据见 [账号与备份](account-and-recovery.md)：只有当前范围覆盖的精确子项处理，才允许在受控本地内存解析指定项，不回显秘密。删除已批准精确项后用相同元数据条件复查，错误码与确证不存在分开。
- Shell 启动文件先定位确属目标的 env/alias/函数/启动命令，保存必要的非秘密局部回退信息，精确修改并比对其他字节。若原文件含秘密，不为了备份导出明文；不能安全保全时保留该对象并说明。
- 上一条是完整卸载和普通成果保全的默认策略。账号维护只有明确接受 `sensitive-recovery` 时才可按逐文件政策保存敏感恢复原件；不把这份批准扩展为整个 shell、浏览器或 Keychain 的导出。
- Shell 历史只处理确认属于目标的行，不能用关键词删除讨论 Claude 的 Codex 命令或研究内容。其他行保序、保字节验证。现有 shell 内存可能回写历史，记录其覆盖局限；不要替用户关闭工作终端或跑 `history -c`。

## Chrome：每个 Profile、每一类独立

### 发现与现场保护

- 正常用户目录通常为 `~/Library/Application Support/Google/Chrome`；先核准实际浏览器版本、通道、启动配置及目录。额外用户目录/非标准 Profile 用已有证据补充，不从标准辅助脚本的结果宣称“全机所有 Chrome”。
- 将目录中的 `Default`、`Profile N` 和 `Local State` 中索引合并。索引值必须是受控根下单一目录名；拒绝绝对路径、`..`、符号链接越界。未支持的索引名称明确列为待检查。
- 只给 Profile 本地标签，不输出邮箱。一个 Profile 可能登录多个网页账号；本机 Profile 清理不是远端“全部账号注销”。
- 记录用户窗口与非目标标签的脱敏身份/数量，区分本轮设置页；尽量用浏览器自身的恢复窗口能力，不把所有 URL 导出。关闭前保护未保存内容。正常退出，不强杀有用户工作的浏览器。
- 恢复时验证实际用户窗口/标签集合。启动出现 Profile 选择页、空白窗口，不等于恢复成功；只关闭属于本轮的窗口。不要重新打开已删 Claude 目标页。

### 目标判定和隐私

默认候选域：`claude.ai`、`claude.com`、`anthropic.com`，当前归属仍需复核。自建或第三方服务域名不内置为目标；增加其他域须有当前使用者的安装/配置/跳转证据。匹配规范化 host 等于目标，或以 `.`+目标结尾；`notclaude.ai`、`claude.ai.example.org` 不是目标。

普通新闻文章、Gmail 邮件、IP 工具、代理文档、多模型扩展不因提及 Claude 被删除。OAuth 最终跳转到共享服务时，只有可核实与目标登录对应的具体记录可纳入；不得删除共享第三方或 Google 域的历史或授权。

URL 在送入日志或模型输出前用通用 URL 解析脱敏，去掉 userinfo、query、fragment；不依赖 `.com/.ai/.xyz` 等后缀白名单。默认仅保留 host、计数、记录 ID；path 只有确认无秘密且对定位必要时才保留。不要转储整页无障碍文本或全库 URL。截图可能含账号信息，尽量读取必要字段，不无故保存截图。

### 类别与验收

| 类别 | 操作与证据 | 常见误判 |
|---|---|---|
| 扩展、PWA、native host | 核实名称/发布者/ID/实际版本，卸载目标，检查各 Profile 与 host 登记 | 官方扩展旧 ID `fcoeoabgfenejglbffodgkkbkcdhcgfn` 不是永远不变；多模型扩展不自动归属 |
| 网站数据 | 官方站点设置精确删除目标的 Cookie、存储、权限；正常退出后分别核查 | 删除普通域名不保证扩展分区 Cookie 已删除 |
| Cookie | 只读 host/name/path/分区等定位元数据；不读值与 encrypted_value | 同域同名可有不同分区；Cookie 名不能证明登录是否有效 |
| Local Storage/IndexedDB/SW/cache | UI 定向站点清理并核对可识别来源目录/元数据 | 不直接编辑 LevelDB，不删整个存储/缓存目录连带其他站点 |
| 密码/Passkey | 当前密码管理器精确目标；本地两套 Login Data 独立核查 | Login Data 为零不证明 Passkey、云端密码库为零 |
| 历史 | 目标域及已证实 OAuth 链；核对选中记录后删除，复核 URL 和 visit 层 | UI 行数、URL 数、访问次数不同；隐藏跳转不一定显示 |
| 下载 | UI 目标记录与实际文件分别处理；只读唯一 download ID 和 chain 行 | 3 行来源链可只对应 1 次下载；空目标路径/已取消也可能留记录 |
| 书签 | 确认是登录入口而非普通资料；逐个精确删除 | 不删所有含 Claude 文本的书签 |
| Preferences | 优先官方设置处理；必要时评估精确非秘密 JSON 条目 | JSON 是混合文件，不能全文件删除，也不能扩大到 SQLite/LevelDB |

Preferences 的直接局部修改只有在**已批准具体字段、Chrome 已完全退出、当前结构已检查、字段确认非秘密且目标独占、能保存最小回退记录**时才考虑。原子写入并保持文件权限，比较修改前后所有非目标字段相等，重开后复核。否则保留并登记；辅助工具不会执行修改。

### UI 删除循环

一次循环：获取当前窗口/Profile → 定位目标域/标题/日期 → 点击准确当前元素 → 重新读选中对象与数量 → 执行一次删除 → 读取新状态 → 核对目标身份消失。页面重排后重新定位。粘贴搜索词后读回输入值，防止焦点错误或首字丢失。不得根据上一张截图坐标/旧索引批量盲点。

卸载扩展可能新开反馈页；不提交反馈，不替用户填表；关闭本轮反馈页，并将它新生成的、明确目标关联历史记录纳入既有清理范围核验。

### 只读持久化复核与常见难点

- 正常退出写入源后以只读方式检查当前 schema；不要用 `immutable` 绕过锁/WAL，也不复制完整数据库。锁定、缺表、权限失败记录为未核验，不能用零填补。
- **分区 Cookie**：记录 Profile、host、name、必要的安全 path 标记、分区来源类型/脱敏标识；本轮 UI 删除若持久库仍在就标 `residual`。不要误判“扩展已卸载所以它没了”或“有它就还登录着”。
- **隐藏下载**：唯一下载对象、来源链行和实际文件分开计数。UI 不显示时查当前官方精确管理方式；两次无效尝试后停止同法重试，不清空整段历史或整库。
- 本技能的只读数据库约束是操作边界，不是“系统永久禁止删除”。正确说法：“在当前约束及已验证方法下尚未删除成功，证据为……”。若用户要求进一步处理，准备新增方法和影响后再判断批准，而非先给无依据保证。

## Safari

仅在当前范围覆盖 Safari 时处理。默认精确域/记录，全部历史与网站数据须明确扩大批准并说明同步影响。历史、网站数据、密码/Passkey、扩展/书签分开验证。权限被拒与未检查不能写零。清理动作前确认当前选中集，列表变化后旧元素 ID 作废。

## Office：不要把“历史登记”当“当前安装”

分别检查四层：当前“我的加载项”/账号加载项，Claude 专属 manifest/存储，混合 entitlement/MRU/WebKit 缓存，指定文档的嵌入关系。

- Excel/Word/PowerPoint 的当前界面分别核对。共享 Wef 等文件含 Claude 资产 ID 只证明历史信息存在，不能证明当前插件在用、不能直接说已卸载。
- 只有确认 Claude 独占的 manifest/存储才进入删除批次；共享文件无法可靠精确处理就保留并解释，不清空全部 Office 缓存、不退出 Microsoft 主账号。
- 不全盘修改工作文档。用户明确指定文档内嵌插件清理时，另做副本、结构检查与原生复开；不得损坏公式、链接或其他插件。
- 测试需要空白文档时，创建并标识本轮自己的文档。现有“工作簿1/文档1”可能是用户未保存的工作，不可写入、关闭或放弃保存。
- 先检查已有进程和窗口，避免激活工具暴露整个用户文档。结束仅关闭本轮窗口；退出验证使用进程状态，不调用会重新启动 App 的入口。

## IDE、旧副本与废纸篓

- VS Code/Cursor 等按本机安装位置、扩展 ID、专属存储核实；不删除整个编辑器配置、多模型插件、项目设置或远端开发机。远端未检查必须说明。
- 安装包只处理实际路径、来源已确认的目标。下载记录删除不会替代删除安装包，下载过的工作 PDF 不因下载自 Claude 就当安装垃圾。
- 备份先列清混合内容与恢复价值；不可将“旧 Chrome 备份”视为纯 Claude 副本。
- 废纸篓受权限限制时可用已授权的 Finder 精确操作；前后核对目标及其他项目数量，禁止整桶清空。不要把文件夹行数、其子文件数和全树文件数混加。
